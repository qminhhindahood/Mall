## Reproduced cause and repair

The baseline opens full-page loading whenever a request crosses into or out of map/Discovery, even when that scene has already completed preparation. Cached presentation still awaits the GPU queue and repeats shader compilation. The resulting loading-state changes mount a modal, hide the canvas and make the guide inert during ordinary reversed scrolling. Revision-keyed scenes and resources were retained: the reproduction does not establish cache loss or context loss.

[T3 Saigon](red-saigon.json) records six overlay openings; [T3 Vincom](red-vincom.json) records two. The [minimal Vincom overview → prepared L2 map → overview sequence](red-minimal-vincom.json) records two. The [standalone baseline](standalone-red.json) independently records six Saigon/twelve Vincom openings over three loops. These counts describe their exact runs, not a universal rate. The owner's supplied screenshot remains in the root draft r3 section 6.

The runtime now records completed preparation only after texture/shader work, a complete offscreen frame and GPU readback. Explorer queries that state rather than reopening the gate for every changed view. Idle cached views draw a complete frame synchronously in the layout phase, without recompiling unchanged shaders. When unrelated background GPU work is active, the existing complete presentation remains until the serialized handoff draws its replacement. Genuinely unfinished scenes retain full-page loading; failures/context loss and disposal invalidate readiness. No assets or quality settings changed.

Affected rapid-history checks also reproduced an inherited bug on [the original baseline](baseline-history.json): pending navigation entries acquired the exterior's departure position, so Back/forward could briefly show Discovery and then reverse to the exterior. The history repair leaves unarrived destination positions unset and guards both position writers while presentation/focus is pending. Actual arrival scrolling records the position; ready locale changes preserve their viewport position. Independent [Standards and Spec review](reviews.json) has no unresolved findings after correcting the busy-GPU and intermediate-history-entry findings.

# Loading foundation — issue 0011

Builds use `MALL_ID=saigon-centre|vincom-dong-khoi`. `npm run build:saigon` and `npm run build:vincom` invoke the selected-mall asset preparation then Astro diagnostics/static generation; independent outputs live under `dist/<mallId>`. No production tenant records are fabricated. Optional reviewed records are `data/malls/<mallId>/destinations.json`; explicit `INCLUDE_TEST_FIXTURES=1` adds one browser-only store fixture for shared-link acceptance. Normal builds exclude it.

`src/data/site.ts` is build-only and imports source geometry. Static pages render the requested/default floor's SVG from those exact records. The React island receives metadata without contour/source arrays plus `geometryUrl`, avoiding full-dataset serialization into each route. The shell fetches `/data/floor-geometry.json` concurrently with dynamic scene-module import. It retains the source-rendered static SVG until fetched geometry can replace it. No Three imports occur in the SSR tree.

Factory: named `createSceneRuntime(options): Promise<SceneRuntime>` from `src/runtime/create-scene-runtime.ts`. Options are `canvas`, `mallId`, complete `data: FloorDataset`, `assetRevision`, `exteriorUrl`, optional `modelBytes: Promise<ArrayBuffer>`, `reducedMotion` and `onStatus`. Runtime methods/statuses are specified in `src/runtime/scene-contract.ts`. The foundation factory deliberately rejects instead of declaring placeholder readiness; issue 0013 replaces it. That later runtime owns parallel GLB transfer, full-frame proof, scheduler/cache, resource lifecycle and context failures.

The four exterior/overview/map/Discovery sections stay in the document. `sceneHosts` supplies their stable DOM mounts. A canvas is imperatively created per runtime attempt in the parking host; React never owns or reparents that node. Runtime may move it into the requested section, and delayed R3F cleanup of an old attempt cannot lose the new attempt's distinct canvas context. Visibility masks it while preparation continues; it is never `display:none`. The shell removes its owned canvas on attempt cleanup and the runtime must dispose its resources.

Canonical paths are `/vi/tang/<id>`, `/vi/cua-hang/<slug>`, `/en/floors/<id>` and `/en/stores/<slug>`, without trailing slashes. `src/data/routes.ts` supplies the shared URL builder. A store's static HTML is floor-neutral: it lists all verified floors and omits active-floor badges/SVG until hydration resolves a valid query selection or primary floor. Unknown production stores are not generated.

The React owner controls requested kind/floor/locale/destination and history. Runtime cannot mutate that selection. Initial entry waits for exterior/overview then requested `show`; subsequent `show` completion is guarded by a request serial. The full-page loading overlay blocks surrounding interactive content with `inert`; errors release the guide. Locale retains its focused control; direct floor links, query floor, Back/forward and browser refresh resolve selection without stale runtime callbacks resetting it. The shell's initial preparation effect will need the real runtime slice's stronger generation/complete-frame coordination before acceptance of scene readiness.

Public browser checks are `tests/browser-shell-checks.js`, intended for T3 preview evaluation against built outputs. No reducer/helper/unit suites. Current source SVG is a source-backed schematic with visible uncertainty, not registered surveyed geometry or an approved directory.
